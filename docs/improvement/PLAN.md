## 順序

状態欄は2026-11-20の実装後に更新した。「完了」は、その行の検証を実際に実行して通ったものだけに付けている。「自動」は `swift test`（81件、失敗0）、「実機」はビルドした.appを隔離モードで起動し、アクセシビリティAPI経由で操作した結果を指す。

## 実装中に見つかり、計画に追加した修正

実機で `yes` を流したところ、メインスレッドが埋まり、状態の取得に約20秒かかった。原因は、出力の読み取りに上限がなく、表示上限を超えるたびに出力欄の全文を置き換えていたことにある。
次の3点を追加して解消した（コミット `e2e8ae3`）。

- UI側に1 MB以上たまったら読み取りを止め、パイプ経由でコマンド側を待たせる
- 上限を超えて落とした行は、出力欄からも先頭の該当分だけを削除する
- 出力欄は画面に見える範囲だけをレイアウトする

修正後、1 MB / 回の更新30回の平均は約10 ms（リリースビルド、最大89 ms）。

## 残っている確認

実物のキーボードとトラックパッドを使う確認は、自動化できなかった。フォーカス中のアプリへキー入力を合成すると、オーナーが作業中の別アプリへ届くおそれがあるため、実施していない。

- `⌃C` / `⌘.` による停止、`Return` / `⇧Return` / `⌥Return`、`↑` / `↓` の履歴呼び出し、`Esc`（日本語入力の変換中を含む）
- トラックパッドで上へスクロールしたときの追従停止と「最新の出力へ」ボタンの表示
- 通常起動（⌥ Space、実際の設定と履歴）での一連の流れ
- 英語とドイツ語以外の言語での新しい文言の表示

## 実機確認手順

自動テストで代替できない操作の確認。隔離された `--ui-fixture` モード（専用の設定・履歴・クリップボード、ショートカットは ⌃⌥⇧Space）で行う。

```sh
bash scripts/build-app.sh
dist/Mini-Terminal.app/Contents/MacOS/Mini-Terminal --ui-fixture
```

1. **逐次表示**: `for i in $(seq 1 20); do printf "\rframe=%d" $i >&2; sleep 0.3; done` を実行し、進捗が1行で更新され、ステータスに経過時間が出ることを確認する。ffmpegがあれば `ffmpeg -f lavfi -i testsrc=duration=20:rate=30 -c:v hevc_videotoolbox -stats -y /tmp/mt.mp4` でも確認する。
2. **停止**: `sleep 60` を実行し、停止ボタン、`⌘.`、`⌃C` のそれぞれで止まることを確認する。実行中にメニューから終了し、`pgrep sleep` に残らないことを確認する。
3. **スクロール**: `seq 1 5000` を実行し、末尾へ追従すること、実行中に上へスクロールすると追従が止まり「最新へ」ボタンが出ることを確認する。50行のスクリプトを分割表示の入力へ貼り、実行中もスクロールできることを確認する。折り返しを切り替える。
4. **コンパクト表示**: `ls -la` で出力ペインが開くこと、`:` では開かないこと、3行のコマンドを貼ると入力欄が伸びることを確認する。
