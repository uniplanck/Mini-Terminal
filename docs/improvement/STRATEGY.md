# Mini-Terminal 改善戦略（v0.5）

作成日: 2026-11-20 / 基準コミット: `cb37de0`（`feat/v0.4-ui-polish-20261007`）

## 判定基準

Mini-Terminalの価値は、⌥ Space で呼び出した短いShell実行が数秒で終わることにある。
この文書の改善案はすべて「1回のコマンド実行が、より速く、より簡単になるか」で採否を決めた。
ならないものは、良い機能であっても入れない。

起動、呼び出し、常駐時の軽さは現状より悪くしない。実装はAppKit + SwiftUIのまま、外部依存は増やさない。

## 現状監査

### 実行エンジン（`ShellRunner.swift`）

長いffmpegジョブで右ペインが「実行中…」のまま止まる原因は、読み取りの方式にある。
stdoutとstderrをそれぞれ `readDataToEndOfFile()` で読み切り、`waitUntilExit()` の後で初めて `completion` を呼ぶため、`AppModel.output` が書き換わるのは終了時の1回だけになる。

同じ箇所から、報告されていない問題も4つ見つかった。

- **停止手段がない。** `Process` の参照を実行中に保持しておらず、UIにも停止操作がない。止めるにはアプリを終了するしかなく、その場合も子プロセスは残る。
- **バックグラウンド子プロセスで終了しなくなる。** `sleep 100 &` のようにパイプを握ったままの子が残ると、シェル本体が終了してもEOFが来ず、「実行中…」が続く。
- **出力順が崩れる。** stdoutを全部並べた後にstderrを連結するので、エラーがどの行の直後に出たかが分からない。
- **不正なUTF-8が1バイトでも混じると出力全体が空になる。** `String(data:encoding:)` が `nil` を返し、`?? ""` で握りつぶしている。

ffmpegの `-stats` は行末を `\r` で上書きして進捗を更新する。したがって逐次表示だけを足しても、進捗が1本の巨大な行として伸び続ける。`\r` の解釈は逐次表示と同時に必要になる。

ログインシェル（`-lc`）の起動コストは実測で約10 ms（`/usr/bin/time -p /bin/zsh -lc :` を3回、いずれも real 0.01）。PATHなどの環境が変わるリスクに対して得られる短縮が小さいため、ここは変更しない。

### 入力と出力の表示（`LauncherView.swift`）

- **コンパクト表示では出力が見えない。** 出力ペインは左右分割時にしか存在しない。コンパクト表示で `ls` を実行すると、見えるのは `exit 0` と所要時間だけで、結果を読むには分割へ切り替える操作が要る。「実行して結果を見る」というこのアプリの中心動作に、毎回1クリック余分にかかっている。
- **コンパクト表示の入力は1行の `TextField`。** 既定で有効な「開いたときに貼り付け」で複数行のスクリプトや長いワンライナーが入ると、全体を確認できない。
- **分割表示の入力は実行中に `.disabled`。** 編集だけでなくスクロールと選択も止まるため、長いジョブの間、自分が何を実行したかを読み返せない。
- **出力は1つの巨大な SwiftUI `Text`。** 出力全体を1ビューとしてレイアウトするので、数万行で重くなる。折り返しがなく、長い行は横スクロールでしか読めない。末尾追従もない。
- **入力欄でスマート引用符などの自動置換が無効化されていない。** システム設定によっては `"` が `“` に置き換わり、コマンドが壊れる。

### 状態表示

- 実行中は「実行中…」だけで、経過時間が出ない。
- 所要時間は常に `%.0f ms` 表記。20分のエンコードは `1200000 ms` と表示される。
- 実行中は出力コピーが無効で、途中経過を持ち出せない。

### 履歴と保存

履歴は出力全文を含めて `UserDefaults` に保存しており、1件ごとの上限がない。
オーナー環境の設定ドメインはすでに399,106バイトある（`defaults export com.nao.mini-terminal - | wc -c`）。
この配列は起動時に全件デコードされ、実行のたびに全件エンコードされるので、大きな出力を数回実行すると起動と実行完了の両方が遅くなる。

常駐中のメモリは、起動21分後のプロセスでRSS 57.6 MB、CPU 0.0%だった（`ps -o rss,%cpu`）。v0.5でこの値を悪化させないことを確認対象にする。

### テスト

`swift test` は28件（1件は環境変数指定時のみ実行）で、基準コミットではすべて成功する。
ただし `ShellRunner` のテストは短いコマンド2件だけで、逐次出力、停止、バックグラウンド子、大量出力はどれも検証されていない。

## 改善案

### A. 出力の逐次表示

| | |
| --- | --- |
| 内容 | stdoutとstderrを1本のパイプにまとめ、届いた順に画面へ反映する。`\r` による行の上書きと、ANSIエスケープ（CSI）の除去を行う。 |
| 簡易性／速度への効果 | 長いジョブの進捗が見える。短いコマンドでも、終了を待たずに最初の行が出る。stderrが発生位置に表示される。 |
| コスト | `ShellRunner` の書き直しと、出力バッファの新設。画面更新は約30 ms間隔にまとめ、大量出力でもメインスレッドを埋めない。 |
| やらないこと | PTYの割り当て、対話入力、色付き表示、カーソル移動の再現。ターミナルエミュレータにはしない。 |

パイプを1本にするとstdoutとstderrを区別できなくなるが、現状もコピーされるのは両者を連結した文字列であり、失う機能はない。

### B. 実行の停止

| | |
| --- | --- |
| 内容 | 実行ボタンが実行中は停止ボタンになる。`⌃C` と `⌘.` でも停止できる。 |
| 簡易性／速度への効果 | 打ち間違えたコマンドや不要になったジョブを、アプリを落とさずその場で止められる。 |
| コスト | 子プロセスを独立したプロセスグループで起動する必要があり、`Foundation.Process` から `posix_spawn` へ置き換える。 |
| やらないこと | タイムアウト設定、一時停止と再開、複数ジョブの並行実行。 |

停止はまずグループ全体へSIGINTを送る。ffmpegはSIGINTでファイルを正しく閉じるので、Terminalの `⌃C` と同じ結果になる。
2秒後に残っていればSIGTERM、さらに2秒後にSIGKILLへ進む。停止操作をもう一度行うと即座にSIGKILLを送る。
シェルだけにSIGTERMを送る方式では、パイプラインの子が残ってしまう。プロセスグループを分けるのはそのためである。

### C. 入力・出力のスクロール

| | |
| --- | --- |
| 内容 | 入力と出力を `NSTextView` ベースに置き換える。入力は実行中も選択とスクロールが可能（編集のみ不可）。出力は縦横スクロール、折り返し切り替え、末尾への自動追従を持つ。 |
| 簡易性／速度への効果 | 貼り付けた長いコマンドを実行前にも実行中にも確認できる。出力は差分だけを追記するので、長い出力でも描画が重くならない。 |
| コスト | `NSViewRepresentable` 2種。SwiftUIの `Text` と `TextEditor` より記述量は増える。 |
| やらないこと | シンタックスハイライト、行番号、出力内検索、補完。 |

自動追従は「最下部にいる間だけ」働く。ユーザーが上へスクロールすると止まり、最下部へ戻るか「最新へ」ボタンを押すと再開する。

### D. UI全体

| 項目 | 内容 | 効果 |
| --- | --- | --- |
| D1 コンパクト表示の出力 | 出力が届いた時点で、コマンド欄の下に出力ペインを開く。 | 分割へ切り替えずに結果を読める。 |
| D2 伸びる入力欄 | コンパクト表示の入力欄が内容に応じて最大6行まで伸び、以降はスクロールする。Returnで実行、`⇧Return` / `⌥Return` で改行。 | 貼り付けたスクリプトの全体が見える。 |
| D3 実行中の表示 | 経過時間と停止操作のヒントを出す。 | ジョブが動いているか止まっているかを判断できる。 |
| D4 所要時間の表記 | `850 ms` / `12.3 s` / `20m 05s` を長さで切り替える。 | 長いジョブの結果を読み替えずに済む。 |
| D5 終了状態 | 失敗は赤、停止は「停止」表示とし、停止時は自動コピーをしない。 | 途中で止めた出力でクリップボードを上書きしない。 |
| D6 途中経過のコピー | 実行中でも出力コピーを有効にする。 | 進捗やエラーをすぐ貼れる。 |
| D7 出力量の上限 | 表示は約200万文字、履歴は1件あたり約2万文字までとし、超過分は古い側から省略して、その旨を表示する。 | 大量出力でも固まらず、履歴が起動を遅くしない。 |
| D8 自動置換の無効化 | 入力欄のスマート引用符、スマートダッシュ、スペル修正を切る。 | コマンドが勝手に書き換わらない。 |

D1とD2はパネルの高さを変えるので、高さの計算は既存の `UIParameters.launcherSize` 1か所に集約したままにする。
出力がないコマンドではパネルは伸びない。短い実行でパネルが開閉してちらつくことを避けるためである。

### E. バージョンと文書

0.5.0へ揃える。仕様が変わる点は `RELEASE_NOTES_DRAFT.md` に利用者の言葉で残す。

## やらないことリスト

次の項目は、要望が出ても今回は入れない。いずれも1回の実行を速くも簡単にもしないか、常駐の軽さを損なう。

- PTY、対話型コマンド（`vim`、`top`、パスワード入力）、ANSIカラー表示
- タブ、複数セッション、複数ジョブの同時実行
- コマンド補完、シンタックスハイライト、スニペット管理、エイリアス管理
- 出力内検索、出力のファイル保存、出力のフィルタ
- テーマ、フォント設定、ウィンドウの自由リサイズと位置記憶
- 完了通知、メニューバーでの進捗表示（下の「次の候補」を参照）
- 履歴の全文検索、タグ、同期
- 外部ライブラリ、Web技術、クロスプラットフォームUIフレームワークの導入
- Windows版との共通化を目的とした抽象レイヤ

## 次の候補（今回は実装しない）

効果は見込めるが、今回の4項目より優先度が低いもの。

- 長時間ジョブの完了通知。パネルを閉じて待つ使い方が増えた場合に検討する。
- 履歴の絞り込み。履歴表示中に入力した文字で一覧を絞る。
- 履歴の保存先を `UserDefaults` からファイルへ移す。D7の上限で当面の肥大は止まる。

## Windows版へ引き継ぐもの

Windows版を作る場合は、OS専用のネイティブ実装を別に書く。Mac版のコードに共通化のための層は入れない。
両者で共有するのは振る舞いの定義だけにする。

置き場所の提案:

```text
docs/spec/
  BEHAVIOR.md      呼び出しから結果コピーまでの振る舞い（OS非依存の言葉で記述）
  OUTPUT.md        出力の扱い: 逐次表示、\r の解釈、上限と省略、末尾追従の条件
  EXECUTION.md     実行と停止: 停止の段階、終了コードの表示規則、履歴に残す条件
  SAFETY.md        実行前確認の対象パターン
```

各文書は「利用者の操作」と「観測できる結果」だけで書き、`NSTextView` や `posix_spawn` のような実装名を含めない。
Windows版はこの定義を満たす別実装とし、シグナルの段階のようにOSで手段が異なる箇所は、定義側に「意図」（穏やかな停止要求 → 強制終了）を書く。
今回この `docs/spec/` は作成しない。v0.5の振る舞いが `RELEASE_NOTES_DRAFT.md` で固まった後に、そこから切り出すのが最短である。
