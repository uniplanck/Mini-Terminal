# v0.4 UI review candidate

Status: implementation and automated checks complete; final interaction acceptance is pending. This is not a public release or an approved filming freeze.

## Scope

Native macOS utility polish, not a terminal replacement. Shared 4pt spacing, 32pt toolbar controls, 40pt history rows, 13pt labels and 14pt code/body text. Compact, split and history sizing use one function. Settings uses three native segmented sections: shortcut/language, clipboard/safety, and shell. Semantic system colors support light and dark appearances; the accent follows macOS.

Copy feedback lives in the footer, so it does not compress the command input. Running state prevents editing and history restoration. The input/output panes align to the top. Completed commands without output have an explicit state. History clearing requires confirmation. Shortcut capture stops on section changes, window close and window loss of focus.

The clipboard flow also avoids executing the app's own copied output on the next open. A fresh external clipboard change is required to ingest another command. Empty command output does not erase the clipboard automatically. Combined input/output copy uses the executed command rather than a subsequently edited draft.

## Evidence, 2026-10-07

- `swift test`: 28 tests, zero failures, including named-pasteboard isolation, history, nine-language catalog coverage, clipboard auto-run/copy regression and native rendering.
- Native render suite: 42 fictional-fixture PNGs covering compact states, split, history, a 640pt narrow layout, light/dark, and all three settings sections in English, Japanese, German and Portuguese. The remaining locales have catalog completeness tests, not a claimed visual pass.
- Representative native renders and contact sheets were inspected. Output alignment, history-divider orientation and duplicate shell-field labels found during review were corrected and rendered again.
- Real native AX interaction: Run button executed the fixture command, displayed the expected output with exit 0, and copied the expected value to a private pasteboard. Settings opened from the actual launcher button; AX reported a retained main/focused settings window. Global application activation and hardware keyboard routing remain unverified.
- External screenshot/keyboard operations were rejected with `Background input is refused while Secure Event Input is enabled.` No protection settings were changed or bypassed.

Local evidence is under ignored `_copy/`: `ui-v04-final/`, `ui-contact/`, `v04-acceptance.json`, and the verification digest. The required remaining checks are native keyboard focus/press feedback, the shortcut/clipboard/history keyboard flow, and final UI-freeze sign-off.

## Reproduce

```sh
MINI_TERMINAL_UI_SMOKE_DIR="$PWD/_copy/ui-v04-final" swift test
bash scripts/build-app.sh
open dist/Mini-Terminal.app
```

The optional `--ui-fixture` launch argument starts an isolated session with fictional data, a private clipboard and temporary preferences. It does not auto-execute at startup; its shortcut is Control+Option+Shift+Space to avoid the normal shortcut. This mode is for local verification, not the normal launch workflow.

## Existing limitations outside this polish

The runner supports finite, non-interactive commands. It does not yet provide a PTY, cancellation, streaming output or an execution timeout. History retains command output locally and is not a secret-safe vault. Large-output limits and history storage controls are separate follow-up work. No WCAG certification, performance benchmark, hardware-keyboard pass, production release, main push or video production is claimed here.
