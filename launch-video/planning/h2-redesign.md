## 2. 正しい配列（基準）

Mac（US / ANSI 配列。MacBook Air・MacBook Pro・Magic Keyboard 共通）の最下段・左側:

```
 ┌────┬───────┬──────┬─────────┬──────────────────────────────┐
 │ fn │control│option│ command │            space             │ …
 │ 🌐 │   ⌃   │  ⌥   │    ⌘    │                              │
 └────┴───────┴──────┴─────────┴──────────────────────────────┘
   1u    1u      1u    ≈1.25u               ≈5u
            ▼ 押す                        ▼ 押す（同時）
```

- 左から **fn / control / option / command / space**。option と space の間には必ず command がある。
- command は option より一回り幅が広い（約 1.25 倍）。画面上でこの差が読めること。
- 押すのは **option（⌥）と space の 2 つ**。間の command は押さない — 「沈んだ 2 つの間に command が立っている」ことが正しい配列の証拠になる。
- **JIS 配列は不可**（space の左隣に「英数」キーが入り、command と space が隣接しない）。
- **英国（ISO）配列**: 最下段の並びは US と同じ。ただし刻印が `alt` / `cmd` 表記の場合があり、`option` / `command` と一致しない。**このMac（MacBook Air M3 `Mac15,12`）の内蔵キーボードは `ioreg` 上 `British` と報告されている** — 撮影前に目視で刻印を確認し、`alt` / `cmd` 表記なら US 配列の Magic Keyboard を使う（推奨）か、表記違いを許容するかを決める。
- Logitech K370/K375 など Mac 以外のキーボードは不可。

## 4. AE レイヤー構成（`PC_H2R_RIG`、JSX が自動で組む）

`build_launch_film.jsx` の `buildS02Rig` が下記を作る。マスク形状だけは写真に合わせて手で描く（JSX は仮の矩形を置く）。

```
S02_KEYS（1.5s）
  ADJ_ImpactPulse        調整レイヤー: 露出 +0.6EV × 3フレーム（打鍵）
  CAM                    カメラ
  BASE = PC_H2R_RIG      3D。スケール 100% → 101.5%（静止画に呼吸を与える最小のプッシュ）
  BG                     #0A0A0B

PC_H2R_RIG（1.5s、プレート解像度ではなく 1920×1080 に fit）
  CTRL_Press             ヌル。スライダー「press」0→1、「travel px」（沈み量）。全押下レイヤーがこれを参照
  SHADE_command_sides    command の左右側面に落ちる影（押下時に両隣が沈んで露出する側面を暗く）
  CAP_space              プレートの複製 + マスク（space キーキャップ全体）。Y = −/+ travel × press
    └ MATTE_well_space   トラックマット（アルファ）: キー穴の縁（Magic Keyboard はベース面との接線）より上だけ表示 → 沈むとキャップ下端が隠れる
  CAP_option             同上（option）
    └ MATTE_well_option
  FILL_well_space        キー穴の中の暗部（プレートからサンプルした暗色、不透明度100%固定）。静止時はCAPに完全に隠れ、沈むと上端の隙間として見える
  FILL_well_option
  PLATE                  H2R-A_rest（全体）
```

ポイント:

- **同時性はヌル 1 本で担保**: CAP_option と CAP_space の位置・露出・影はすべて `CTRL_Press` の `press` をエクスプレッションで参照する。キーフレームは `press` の 2 つだけなので、2 キーがずれて沈むことは構造上起きない。
- **沈み量**: 実機のキーストロークは約 1mm。`travel px ≈ (option キーキャップ幅 px ÷ 15.5mm) × 1.0mm`（プレートを comp に fit した後の px で測る）。参照写真 B があれば、A と B の差分で実測して上書きする。初期値 6px。
- **command は一切動かさない**。両隣が沈むことで command の側面が少し露出する → `SHADE_command_sides` で暗く締める。
- **光の変化**: press=1 で CAP の露出 −0.25EV（リムライトから外れる）。FILL_well は常に 100%（フェードさせると元のキャップ上端が二重に透ける）。B を参照して色と露出を合わせる。
- **マスクは手描き**: JSX は CAP / FILL / MATTE に仮の矩形マスクを置き、ガイドに「要トレース」と表示する。プレートが届いたら 3 種を同じキー輪郭から作る（CAP と FILL は同一パス、MATTE は縁のラインから上）。
- 合成用に PLATE はリニア 16-bit（プロジェクト 16bpc）で扱う。

3. `planning/timeline.json` → `S02.press.masks` に `"H2R-A_rest.png": { "travelPx": …, "radius": …, "option": [...], "command": [...], "space": [...] }` を追加。`travelPx` は comp px（目安: option のキーキャップ幅 px × 0.96 ÷ 15.5 × 1.0mm × 画角による係数）。
4. AE を開いた状態で実行:
   `osascript -e 'tell application "Adobe After Effects 2026" to DoScriptFile "<launch-video の絶対パス>/ae/scripts/verify_s02.jsx"'`
5. レポートを読む（AE の環境設定ファイル内 `Settings_MiniTerminalVerify`。スクリプトはファイルを書けない設定のため）。expression errors: none、CAP 位置の一致、レンダー差分で command 内部が基準値のままであることを確認。
6. `preview/verify_s02/` の押下前（f52）・押下後（f62）を見比べ、キー縁の残り・マットの段を目視確認。必要なら角の座標を詰めて 4–6 を繰り返す。

マスク定義がない画像を置いた場合、リグはキーを動かさずプレートだけを表示し、`NO MASK SET` マーカーを付ける（誤ったマスクで押下しない）。
